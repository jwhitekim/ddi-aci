# Proposal

## Why

B·C 실행 환경과 실행기는 준비됐지만, 무엇을 물어보고 어떻게 채점할지가 아직 코드로 없다. DSN-DDI 논문의 벤치마크는 모델 성능을 재므로, "에이전트가 모델 결과를 올바른 의미로 전달했는가"를 재려면 질문·정답·채점기를 새로 만들어야 한다. 사용자와 **간단 버전(10문항, 한 가지 유형)**으로 확정했다(`eval_spec.md`). 스모크 테스트에서 B가 실제로 번호 체계·방향·모델 선택을 틀렸으므로, 이 오류들을 자동으로 잡는 채점이 필요하다.

## What Changes

- **질문 생성기**: DSN-DDI fold0 테스트셋에서 seed 42로 10쌍(서로 다른 관계 10개)을 뽑아 `{A}이랑 {B} 상호작용 예측해줘` 질문을 만든다
- **정답 생성기** (예측 서버와 독립): 원 DSN-DDI 코드로 쌍 하나씩, 두 순서 모두 계산해 `eval/questions/questions.jsonl`에 저장한다
- **채점기**: 결과를 정규화(이름 → ID, 문장 → 효과·방향)하고, 방향마다 ①모델 결과 ②효과 종류 ③방향을 판정해 성공·부분 정답·실패 원인·지표를 계산한다. A·B·C 모두 같은 기준
- **A 실행기**: 도구 없이 LLM API로 답을 받는다. A의 답은 채점기 모델 두 개가 효과·방향을 뽑는다
- **10문항 실행**: A·B·C로 실제 실행(약 5~6달러)하고, 10문항 전부를 사람이 확인해 채점기와 비교한다
- 이번 변경으로 끝낸다. 다른 질문 유형과 문항 확대는 하지 않는다

## Capabilities

### New Capabilities
- `eval-set`: 평가 질문 10문항과 정답(두 순서의 모델 출력)을 만드는 규칙과 형식
- `eval-scoring`: A·B·C 결과를 정답과 비교해 성공·부분 정답·실패 원인·지표를 계산하는 규칙

### Modified Capabilities
(없음 — C 도구는 바꾸지 않는다. 두 방향이 필요하면 에이전트가 `ddi.predict`를 두 번 부른다)

## Impact

- 새 코드: `eval/` (질문·정답 생성, 채점, A 실행기, 배치 실행), `eval/questions/questions.jsonl`, 결과 기록 `eval/RESULTS.md`
- 문서: `eval_spec.md`(평가 명세, 근거), `ddi-draft.md` 6장
- 비용: 약 5~6달러 (Vercel AI Gateway)
