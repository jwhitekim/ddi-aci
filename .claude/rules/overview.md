# 프로젝트 개요

## 무엇을 하는 연구인가
- **DDI-ACI**: LLM 에이전트가 약물 상호작용 예측 모델 DSN-DDI 를 운용하도록 돕는 모델 특화 에이전트-컴퓨터 인터페이스(ACI). SWE-agent 의 ACI 개념(고정된 LLM 을 두고 인터페이스만 설계)을 과학 예측 모델로 확장한다.
- **연구 질문**: 같은 LLM 과 같은 에이전트(OpenHands CodeActAgent)에서, 모델 특화 ACI 가 정확성 실패를 줄이는가.
  - 실행 가능성(executability): 결과 파일까지 도달했는가
  - 정확성(correctness): 실행은 됐지만 모델 출력을 의미상 맞게 전달했는가. 이 연구가 다루는 실패는 "실행은 되지만 의미가 틀린" 쪽이다
- **대상 사용자**: DDI 도메인 지식은 있지만 ML 모델을 직접 다루기 어려운 연구자 (약학, 임상, 실험).

## 왜 어려운가 (ACI 가 담는 것)
DSN-DDI 는 관계 번호(0~85)만 출력하고, 이를 문장으로 바꾸는 규약을 무시해도 에러가 나지 않는다.
- 설명 파일에 번호 칸이 두 개다. 맞는 칸은 `Interaction type == t + 1` (`DDI type N` 아님)
- 86종 중 42종(`Subject == 2`)은 약물 순서가 입력과 반대
- 여러 쌍을 한 배치로 묶으면 예측이 달라진다
- 이 규칙들은 C 의 도구(`explain`, 예측 서버) 안에만 둔다. B 에게는 알려 주지 않는다 (평가 대상). micro agent 프롬프트에도 사용법만 적고 규칙은 적지 않는다.

## 설계 결정과 이유
| 결정 | 이유 |
|---|---|
| OpenHands 0.62.0(마지막 V0) 고정 | 인용 논문(OpenHands, CodeAct)과 같은 구조. V1 에서는 CodeActAgent·micro agent·AgentSkills 가 제거됨 |
| `ddi` 는 IPython 에 import 되는 패키지 | 새 행동 유형을 만들지 않아 B·C 의 행동 형식이 같고, 차이는 인터페이스뿐 |
| B 에게도 DSN-DDI 환경, 저장소 코드, 설명 파일, 약물 이름 사전, 위치 안내를 줌 | 안 주면 B 가 실행 단계에서 막혀 정확성을 비교할 수 없고, B·C 차이가 "환경 + ACI" 가 된다 |
| B 컨테이너에 `ddi`·서버 코드를 아예 두지 않음 | 파일이 남아 있으면 B 가 찾아서 쓸 수 있다 |
| 최대 30턴 | 10턴에서는 B 가 탐색에 턴을 다 써서 결과까지 가지 못했다 |
| 웹 브라우징·MCP 끔 | 웹에서 DSN-DDI 규칙을 찾아보지 못하게 |
| 단계별 ablation(C′) 없음 | 실험 단순화. 논문 한계 절에 밝힘 |

## 결과 (v2, 10문항, Claude Sonnet 5.5)
- 성공률 A 10%, B 70%, C 100%. 평균 턴 B 11.4 → C 3.2. 프롬프트 토큰 약 38만 → 4.2만.
- B 는 모델 1위 번호는 10/10 맞혔고, 실패는 번호→문장 대응 오류 2, 방향 오류 1.
- 예비 연구다: 모델 하나, 10문항, 문항당 1회, McNemar p = 0.25. 성공은 모델 출력과의 일치이지 임상적 타당성이 아니다.
- 사후 결정(성공 기준을 한 방향으로 바꿈, A 채점기를 하나로 정함)은 논문에 밝힌다. 상세는 `benchmarks/ddi/eval_spec.md`.
