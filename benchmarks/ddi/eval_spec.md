# DSN-DDI Agent 평가 명세서 (간단 버전, 확정)

> 평가 방법은 이 연구에 맞게 새로 만들고, 평가 방식(지표·채점 구조)만 기존 벤치마크에서 가져온다 (7장).

## 0. v2 기준 (2026-10-12, B·C 재실행 전에 확정 — 아래 4·5장보다 우선)

**바꾼 이유:** v1 실행(`eval_outputs/eval_v1/`, `results/v1/RESULTS.md`)에서 과제 지시가 관계 번호 표기(0부터/1부터)와 예측 순서를 정하지 않아, B가 1부터 세는 번호를 써서 문장이 맞아도 틀린 것으로 채점되었고, C는 한 순서만 계산했다. 그래서 지시와 채점 기준을 다시 정하고 B·C를 다시 실행한다. A는 도구가 없고 질문이 같아 다시 실행하지 않는다.

**과제 지시 (`benchmarks/ddi/agent/task_suffix.txt`, B·C 공통):** 질문 순서대로 첫 약물을 drug_a, 두 번째를 drug_b로 예측 / relation에는 모델이 출력한 관계 번호(0~85)를 그대로 / description에는 그 관계를 설명하는 문장 / 끝나면 finish 도구로 종료. 번호→문장 대응법과 약물 방향 규칙은 알려 주지 않는다 (평가 대상).

**채점 (A·B·C 같은 기준):**
- 질문 순서(= 데이터 저장 순서) 한 방향만 본다. 반대 순서는 보지 않는다
- **성공:** 그 방향의 결과 문장이 모델 1위와 같은 효과(②)이고 약물 방향(③)도 맞음
- 결과 파일에서 그 방향의 대표 행은 확률이 가장 높은 행
- relation 번호가 모델 1위와 같은지(①)는 참고 지표로 따로 적는다 (A는 번호가 없음)

**A 채점기 (2026-10-13, A 결과 확인 후 결정):** Gemini 3.5 Flash 하나로 정한다. 답변 모델(Sonnet 5.5)과 다른 모델이 채점하도록 하기 위함이다. 실행 전에 받아 둔 Sonnet 5.5 추출 결과는 일치율 참고용으로만 보고한다 (10문항 중 3문항 일치).

**사람 확인:** 선택 사항 (4장 검증 참고).

**지표:** 성공률(주 지표), 결과 파일까지 실행한 비율, 번호 일치율(참고), 실패 원인, 효율(턴·시간·토큰)

**실행:** B·C 10문항, 문항당 1회, 시간 초과 20분·실행 횟수 30회에 걸리면 그 상태로 끝내고 다시 돌리지 않음. 채점은 그때까지 저장된 결과 기준

## 1. 목적

같은 LLM(Claude Sonnet 5.5)과 같은 에이전트 구조(OpenHands CodeActAgent)에서, 전용 도구(model-specific ACI, 이전 표기 domain-specific ACI)를 가진 C가 일반 에이전트 B보다 **DSN-DDI 결과를 올바른 의미로 전달하는지** 확인한다.

- 예상: B는 실행은 하지만 관계 번호·약물 방향을 틀린다 (스모크 테스트에서 실제로 관찰됨)
- 문항이 10개라 통계적으로 강한 주장보다는 **경향과 실패 사례**를 보이는 것이 목적이다

## 2. 질문 (10문항)

- **유형:** 한 가지. `{A}이랑 {B} 상호작용 예측해줘` (질문 문장은 순서를 지정하지 않음. v2에서는 B·C 공통 안내 문장이 질문 순서대로 예측하도록 정함, 0장)
- **출처:** DSN-DDI `drugbank/fold0/test.csv`
- **조건:** 두 약물 모두 fold0 train에 있고(transductive), DrugBank 약물 사전에 이름이 있음
- **추출:** seed 42, 서로 다른 관계 번호 10개가 나오도록 뽑음
- **약물을 적는 순서:** 데이터 저장 순서
- 모든 질문 뒤에 B·C 공통 안내 문장(`benchmarks/ddi/agent/task_suffix.txt`)을 붙인다

## 3. 정답

- 원 DSN-DDI 모델·가중치·데이터 처리 코드로 직접 계산 (예측 서버 코드와 독립된 스크립트)
- 쌍 하나씩 계산 (여러 쌍을 묶으면 배치 섞임으로 값이 달라짐)
- DSN-DDI는 약물 순서에 따라 결과가 달라질 수 있으므로 **두 순서 모두** 계산
- 순서마다 1위 관계, 확률, 방향이 반영된 문장 (`Interaction type == t + 1`, `Subject == 2`이면 순서 뒤집기)
- 저장: `benchmarks/ddi/data/questions/questions.jsonl` (질문, 약물 ID, 두 순서의 정답, 테스트셋의 실제 관계 `label`)

## 4. 채점 (A·B·C 모두 같은 기준)

**정규화:** 약물 이름은 DrugBank ID로, 문장은 86개 설명 틀에 맞춰 **(효과 종류, 누가, 누구에게)**로 바꾼다. 그래서 이름 표기나 순서 선택과 상관없이 의미로 비교한다.

**판정:** 에이전트가 말한 방향 하나마다 세 가지를 본다.

| 확인 | 내용 |
| --- | --- |
| ① 모델 결과 | 그 순서에서 모델이 낸 1위 관계를 얻었나 |
| ② 효과 종류 | 번호를 올바른 효과로 바꿨나 |
| ③ 방향 | 누가 누구에게 영향을 주는지가 맞나 |

**성공:** 두 방향을 모두 말했고 둘 다 ①②③이 맞음. 한 방향만 맞으면 **부분 정답**. 말한 방향 중 하나라도 틀리면 성공이 아님.

**실패 원인 (틀린 문항마다 기록):** 실행 실패 / 약물 식별 실패 / 한 방향만 보고 / 모델 선택 오류 / 번호 체계 오류(±1 밀림 등) / 방향 오류 / 배치 섞임(확률이 1e-3 넘게 다름) / 기록 베끼기(모델 대신 데이터 기록을 그대로 냄)

**A 채점:** A는 문장으로만 답하므로, 채점기 모델 두 개가 A의 답에서 (효과 종류, 누가, 누구에게)를 뽑는다. 둘이 같으면 채택, 다르면 사람이 확인. 판정은 위와 같다. 채점기 모델은 실행 전에 정한다.

**검증 (선택, 2026-10-13 변경):** 사람이 10문항을 직접 보고 채점기 판정과 비교하는 것은 선택 사항이다. 확인표는 `results/baseline_a/a_grading_check.md`.

## 5. 결과로 보는 숫자

| 지표 | 정의 |
| --- | --- |
| **성공률 (주 지표)** | 성공한 문항 비율 |
| 실행 가능성 | 결과(CSV)까지 도달한 문항 비율 |
| 해석 정확도 | ①이 맞은 방향 중 ②③도 맞은 비율 |
| 실패 원인 분포 | 원인별 개수 |
| 효율 | 문항당 턴 수, 토큰, 비용, 시간 |

## 6. 실행 조건

| 조건 | 구성 |
| --- | --- |
| A | 도구 없이 LLM API로 바로 답함 |
| B | OpenHands 0.62.0 CodeActAgent + DSN-DDI 저장소·데이터·설명 파일·약물 사전 |
| C | B + 전용 도구(`ddi`, 예측 서버, 설명서) |

- 같은 LLM(Sonnet 5.5, temperature 0.0, 확장 추론 없음), 최대 30턴, 같은 캐싱 설정, 웹 브라우징·MCP 끔
  - 실행 후 확인 (2026-10-15): 추론 강도는 따로 설정하지 않은 기본값이며, v2 실행에서 추론 토큰이 발생했다(`results/RESULTS.md` 3장). 캐싱은 B·C에만 해당한다
- 질문당 1회, 문항당 타임아웃 20분
- 예상 비용: 약 5~6달러 (B 약 0.5달러 × 10, C 약 0.05달러 × 10, A는 미미)
- 기준을 결과 보기 전에 정했다는 기록을 위해, 실행 전에 이 문서를 커밋한다

## 7. 참고한 벤치마크 (평가 방식만 참고)

- **ScienceAgentBench** (Chen et al., ICLR 2025): 지표 구성 — 유효 실행률, 성공률, 비용
- **CORE-Bench** (Siegel et al., 2024): 정답 = 제공된 코드와 데이터를 실행한 결과
- **SUPER** (Bogin et al., 2024): 연구 저장소 기반 과제, 문항 자동 생성
